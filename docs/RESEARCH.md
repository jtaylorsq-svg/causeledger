# Comparable projects and positioning

Research checked 2026-10-25 using project-owned documentation and repository descriptions. This is a bounded comparison, not a full code audit or proof that a feature is absent.

| Project | Publicly documented focus | CauseLedger's narrower design choice |
| --- | --- | --- |
| [ERPNext quality management](https://docs.frappe.io/erpnext/quality-management) | Quality management within a wider ERP, including inspections and quality actions | An independent investigation workbench with no ERP installation |
| [pHKapa](https://github.com/pHAlkaline/phkapa), [project site](https://phkapa.net/) | Nonconformity/CAPA workflow with planning, verification, revisions and action effectiveness | Explicit occurrence/escape cause paths and evidence-dependent closure rules in a small Python domain engine |
| [OpenProject](https://github.com/opf/openproject), [project site](https://www.openproject.org/) | General project/task management, planning and collaboration | Manufacturing-specific evidence, failure mechanism, cause verification and effectiveness as first-class records |

## What the evidence supports

CAPA software and open-source alternatives already exist. "An open-source CAPA tool" is not an original positioning claim. Existing products may be the better choice for organizations needing mature access control or collaboration.

The opportunity to test is narrower: can a facilitator use a lightweight local workbench to make weak evidence and incomplete closure immediately obvious, without fitting an entire ERP or general task manager around the investigation?

The key distinction is the implemented policy: an action can be completed yet the case remains open because effectiveness is missing; a cause can be proposed yet cannot support an action until it has accepted verification evidence; withdrawing proof changes readiness.

## Naming

CauseLedger conveys cause reasoning plus a traceable record. A focused exact-name web search did not surface an obvious competing corrective-action product. This is not trademark, domain, GitHub namespace or package-registry clearance. Repository/package availability must be checked before publication. No domain or package name has been purchased or reserved.

## Validation still needed

Independent quality practitioners must test whether the gates are useful, comprehensible and appropriately strict. Current design and automated tests are evidence of implementation, not evidence of market demand, usability, defect reduction or external adoption.
