# Roadmap

These are genuine outstanding requirements, not claims of user demand or existing GitHub issue activity. Issue drafts are in `docs/issue-backlog.json`; none has been published yet.

## Before v0.1 public release

- Complete browser QA: new case, full demo, save/reload, blocked closure, correction, evidence withdrawal, print, export, stale revisions; desktop and narrow mobile layouts, keyboard operation and console errors.
- Capture actual screenshots with fictional data.
- Completed: separate public repository and sanitized source published; Python 3.11/3.12/3.13 CI passed. See [qualification evidence](QA-2026-11-15.md). This does not close the browser acceptance gate.
- Enable private security reporting and check package/name availability.

## v0.2: make investigations easier to maintain

- Explicitly retire/replace disproven hypotheses while retaining reasons and proof.
- Revise action ownership, dates and plans with tested downstream invalidation.
- Validate and restore exports with migration/version handling and atomic rollback.
- Preserve evidence files with content hashes, size/type limits and safe download handling.

## Later: teams, only after a threat model

- Authenticated identities, role-based authorization and durable externally anchored audit records.
- A supported shared-server adapter, encrypted transport, backup/restore guidance and concurrent-user tests.
- Structured numeric effectiveness plans/results and review of missed sample windows.
- Reusable generic investigation templates and related-case learning, based on practitioner feedback.

Not planned now: autonomous cause verification, automatic product-release approval, full ERP, invented compliance badges or organization-specific customer procedures.
