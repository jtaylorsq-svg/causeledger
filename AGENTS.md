# Repository working rules

- This repository contains only generic workflows and fictional examples.
- Never copy private repositories, customer procedures, production data, credentials or employee/customer identifiers into code, fixtures, issues or screenshots.
- Preserve Evidence → Failure Mechanism → Verified Cause → Corrective Action → Effectiveness.
- Keep occurrence/escape and prevention/detection separate.
- No fabricated adoption, activity, contributors, security validation or compliance claims.
- Keep the default service loopback-only until a reviewed authentication/authorization design is implemented.
- Run Python unit tests, compilation, JavaScript syntax checks and the release-hygiene script for relevant changes. Browser QA is required for UI releases; disclose when unavailable.
- Do not create placeholder issues merely to increase activity. Every issue needs a concrete problem and acceptance criteria.
